# Подключение AI

Этот документ объясняет, зачем в проекте нужен AI, как его безопасно подключить и какие части лучше давать студентам.

## Зачем нужен AI

В игре AI можно использовать для живых текстов.
AI может:

- отвечать от лица подозреваемых;
- сохранять характер персонажа;
- формулировать подсказки;
- анализировать финальную версию игрока;
- писать итоговый комментарий детектива.

AI не должен управлять сюжетом.

## Главное ограничение

AI нельзя разрешать менять факты дела.
Модель не должна:

- менять преступника;
- придумывать новые улики;
- придумывать новые места;
- придумывать новые события;
- делать невиновного персонажа виновным;
- раскрывать преступника раньше финала;
- противоречить карточке персонажа.

## Учебный режим без API

Для первых занятий лучше использовать режим без настоящего API.
В этом режиме ответы подозреваемых уже записаны в словаре Python.
Плюсы:

- не нужен интернет;
- не нужен API-ключ;
- ответы не ломают сюжет;
- детям проще понять код;
- проще тестировать игру.

Текущий `main.py` работает именно так.

## Где находится заглушка AI

В проекте есть отдельный файл:

```text
AI_client.py
```

Сейчас он работает как безопасная учебная заглушка без API.
В нем есть функции:

- `build_character_prompt()` - собирает промпт для персонажа;
- `get_character_answer()` - возвращает готовый ответ персонажа;
- `analyze_player_version()` - дает учебный комментарий к версии игрока.

Пример простой заглушки:

```python
def ask_AI(prompt):
    return "Это учебная заглушка. Здесь позже будет ответ AI."
```

Позже внутри `AI_client.py` можно добавить настоящую функцию запроса к API и подключить ее вместо готовых ответов.

## Настоящее подключение через API

AI поддерживает API, похожий на OpenAI Chat Completions API.
Обычно подключение состоит из шагов:

1. зарегистрироваться в AI;
2. создать API-ключ;
3. сохранить ключ в переменную окружения;
4. установить библиотеку для запросов;
5. написать функцию отправки запроса;
6. использовать эту функцию в допросах или финальном анализе.

## Как хранить API-ключ

API-ключ нельзя писать прямо в коде.
Плохой вариант:

```python
api_key = "sk-..."
```

Хороший вариант:

```bash
export AI_API_KEY="ваш_ключ"
```

На Windows PowerShell:

```powershell
$env:AI_API_KEY="ваш_ключ"
```

В Python ключ можно получить так:

```python
import os

api_key = os.getenv("AI_API_KEY")
```

## Установка библиотеки

Для простого HTTP-запроса можно использовать библиотеку `requests`.
Установка:

```bash
pip install requests
```

Если проект будет использовать официальный OpenAI-совместимый клиент, подключение может выглядеть иначе. Перед занятием преподавателю лучше проверить актуальную документацию AI.

## Пример функции запроса

Ниже пример учебной функции. Ее лучше давать детям не сразу, а после того, как консольная версия уже работает.

```python
import os
import requests


def ask_groq(prompt):
    api_key = os.getenv("GROQ_API_KEY")

    if not api_key:
        return "AI не подключен. Проверь переменную GROQ_API_KEY."

    response = requests.post(
        "https://api.groq.com/openai/v1/chat/completions",
        headers={
            "Authorization": f"Bearer {api_key}",
            "Content-Type": "application/json",
        },
        json={
            "model": "openai/gpt-oss-20b",
            "messages": [
                {"role": "system", "content": "Ты персонаж детективной игры. Отвечай только на русском языке."},
                {"role": "user", "content": prompt},
            ],
            "temperature": 0.8,
        },
        timeout=500,
    )

    response.raise_for_status()

    data = response.json()

    return data["choices"][0]["message"]["content"]
```

## Промпт для подозреваемого

Для каждого подозреваемого нужно передавать модели карточку персонажа.
Пример:

```text
Ты играешь роль подозреваемого в детективной игре.

Имя: Марк.
Роль: программист.
Характер: умный, спорит, хочет доказать свою правоту.
Алиби: говорит, что тестировал звук в переговорной.
Секрет: хранил на флешке старую версию проекта.

Факты дела:
- Пропал прототип обучающей игры.
- Файл исчез за час до презентации.
- В журнале пропусков есть вход Марка.
- На клавиатуре следы сладкой газировки.
- На столе Марка нашли флешку.

Правила:
- Отвечай только на основе этих фактов.
- Не придумывай новые улики.
- Не меняй преступника.
- Не признавайся прямо, если игрок не доказал вину.
- Отвечай коротко, 1-3 предложения.

Вопрос игрока:
Где вы были во время пропажи?
```

## Промпт для анализа версии игрока

В финале можно попросить AI оценить рассуждение игрока.
Пример:

```text
Ты помощник преподавателя на детском интенсиве по Python.

Игрок расследовал дело.

Правильный преступник: Марк.
Правильное объяснение:
Марк украл прототип, потому что хотел показать старую версию проекта.
Его выдали журнал пропусков, следы на клавиатуре и флешка.

Версия игрока:
Марк виноват, потому что он заходил в комнату и у него была флешка.

Задача:
- мягко оцени ответ игрока;
- скажи, какие аргументы верные;
- подскажи, что можно было объяснить лучше;
- не пиши слишком длинно;
- обращайся дружелюбно.
```

## Безопасная точка подключения в проекте

Запрос к AI не нужно вставлять прямо внутрь `interview_suspect()`.
В проекте уже есть отдельная функция:

```python
def get_character_answer(suspect, question_key, question_text, case_data):
    prompt = build_character_prompt(suspect, question_text, case_data)
    return ask_AI(prompt)
```

В текущей версии она работает без интернета и возвращает готовые ответы из `data.py`.
Так проект остается понятным:

- одна функция готовит промпт;
- одна функция отправляет запрос;
- одна функция проводит допрос.

## Что дать готовым

Преподавателю лучше дать готовыми:

- хранение API-ключа;
- функцию запроса к AI;
- обработку ошибки, если API не отвечает;
- запрет на изменение фактов;
- пример промпта.

## Что можно дать студентам

Студентам можно дать:

- написать карточки персонажей;
- придумать факты дела;
- улучшить вопросы;
- улучшить подсказки;
- сравнить готовые ответы с ответами AI;
- протестировать, не придумывает ли модель лишнего.

## Что важно проверить перед занятием

Перед занятием преподавателю нужно проверить:

- есть ли рабочий API-ключ;
- хватает ли баланса;
- работает ли интернет;
- не изменился ли адрес API;
- не изменилось ли название модели;
- есть ли запасной режим без API.

Запасной режим обязателен. Если API не работает, занятие должно продолжаться на готовых ответах из Python-словарей.
