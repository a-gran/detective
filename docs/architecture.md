# Архитектура проекта

Этот документ объясняет, как устроен проект "Интерактивный детектив".

## Общая идея

Проект сделан как консольная игра на Python.
Игрок проходит расследование:

1. выбирает сложность;
2. читает описание дела;
3. изучает подозреваемых;
4. изучает улики;
5. задает вопросы;
6. использует подсказки;
7. выбирает преступника;
8. получает результат.

## Структура проекта

```text
intensive_detective/
├── main.py
├── data.py
├── deepseek_client.py
├── menu.py
├── difficulty.py
├── game_state.py
├── final.py
├── case.py
├── suspects.py
├── clues.py
├── interview.py
├── hints.py
├── README.md
└── docs/
```

## Что находится в main.py

`main.py` является готовым файлом запуска.
Он импортирует функции из отдельных файлов-заданий и соединяет действия игрока в один игровой цикл.
Ученики обычно не меняют `main.py`.

## Что находится в data.py

`data.py` является заданием для создания данных.
В нем нет готового расследования.
В нем есть пустые переменные, типы данных и комментарии, что нужно вставить.

## Файлы команды 1

Команда 1 отвечает за игровой процесс.

- `menu.py` - главное меню и правила;
- `difficulty.py` - выбор сложности;
- `game_state.py` - состояние игры, меню расследования и история;
- `final.py` - финальное обвинение.

## Файлы команды 2

Команда 2 отвечает за действия расследования.

- `case.py` - показ дела;
- `suspects.py` - показ и выбор подозреваемых;
- `clues.py` - показ улик;
- `interview.py` - допрос;
- `hints.py` - подсказки.

## Что находится в deepseek_client.py

Файл `deepseek_client.py` нужен для будущего подключения DeepSeek.
Сейчас он работает как учебная заглушка:

- собирает промпт для подозреваемого;
- возвращает готовый ответ из словаря `answers`;
- показывает короткий комментарий к финальной версии игрока.

## Независимая проверка файлов

Каждый файл задания можно запускать отдельно.
Например:

```bash
python difficulty.py
```

Так ученик проверяет только `difficulty.py` и не зависит от того, готов ли `menu.py`.
